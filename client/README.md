# Client owners

`ReliableProducer(logId, producerId, nextSequence)` owns one fixed proposal buffer and one Cluster session. IDs are provisioned and never reused in their documented scope. `submit` refuses invalid data, exhaustion or a full slot without allocation. `poll` retries the same bytes after lost replies; reconnect with a fresh context. Accepted/duplicate receipts must match the log, producer sequence, source/clock/times and payload before the pending slot clears. Ordinary correlated rejection leaves the bytes available and pauses offers; inspect `lastStatus()` and use `retryPending()` after resolving its cause. Bad receipts stop the owner. An application result may wrap the original payload in a bounded SBE prefix containing groups and variable data, followed by a uint32 original-input length.
The producer validates that generic framing and compares the complete original input before clearing its slot;
it does not interpret application-specific fields. Pass-through results contain only the original payload.
The result prefix is bounded to 2 MiB globally; the application declares its smaller capacity before readiness.
Configure the egress channel to fit `Wire.RESULT_OVERHEAD + limits.eventBytes()` plus
`AeronCluster.SESSION_HEADER_LENGTH`. See [capacity and transport sizing](../docs/application-contract.md#capacity-and-transport-sizing).

Producer memory survives reconnects, not process loss. If pre-admission loss is forbidden, the collector must completely record the exact pending proposal in its capture Archive before its first Cluster offer. Recovery reads the latest complete captured proposal for the same provisioned producer, constructs the producer with its recorded producer sequence, and calls `restoreExact`. Since there is only one outstanding proposal and the next proposal is not captured until the preceding receipt arrives, the latest captured proposal is either pending or the sequencer's latest admitted proposal. Reoffering a valid contiguous pending proposal obtains acceptance or its original duplicate receipt; ordinary rejection remains retained and explicit. An earlier capture checkpoint alone is insufficient: recover the latest complete capture suffix. Archive storage synchronization and power-loss guarantees must be configured and tested separately.

`poll(false)` keeps egress and keepalives live while suppressing offers/retries, allowing an application-owned complete-capture fence to control admission. It still consumes receipts from earlier offers. `poll()` delegates to `poll(true)`; this gate does not assert durability itself.

`CatalogSubscription` independently follows recorded output through `REPLAY_ALL_AND_FOLLOW`. Its callback receives borrowed bytes and a reused `SequencedEventDecoder`; finish application effects before returning. The application owns an atomic state-and-sequence checkpoint. An exception stops delivery without advancing the application cursor; restore application state before restarting.

Compose `EventHandler` callbacks once during setup with `first.andThen(second)`. Each callback sees the SBE payload cursor rewound, including nested chains. Failure propagates and prevents later callbacks without undoing earlier effects. One chain shares a cursor and checkpoints all grouped state together; independent recovery/pace requires separate subscriptions. Never modify borrowed bytes or rebind the shared outer decoder. See the [collector/consumer contract](../docs/application-contract.md) for Agent lifecycle, source profile v1, clock/lineage and conformance rules.

Startup `RecordingCatalog.rebuild` scans complete canonical frames from recordings on the requested stream with alias `spine-output`. The default overload qualifies from sequence one. The checkpoint overload accepts trusted application state at sequence S and requires complete retained coverage from S+1 through an independently observed recorded head. A checkpoint beyond that head, including a nonzero checkpoint with no retained output evidence, fails as unavailable history. `CatalogSubscription` uses its restored/current successful application cursor as this boundary; a cursor without the corresponding application state is insufficient.

Qualification checks log identity and contiguous sequences within each retained source, then SHA-256 equality of every overlapping event after S. Earlier bytes are not compared or applied again. Multiple active sources are supported. Scanning is O(retained history) and temporary hash storage is O(retained suffix after S); both remain cold and do not run from idle polling. Physical byte positions are source-local; they cannot replace logical application cursors. Mixed logs on this stream/alias and a sparse index remain unsupported.

Recording/start/stop positions come from the Archive protocol, so the consumer does not need the recorder's mapped counters. Qualification rereads each retained start, and replay checks it again before opening. A purge beyond the chosen position or another replay-open failure stops recovery explicitly; reopen with restored application state and a fresh catalog. Qualification is not a retention lease. Keep the required suffix available until consumers have durable checkpoints beyond it.

Delivery selects one qualified source at a time. The dispatcher retains 1,024 fixed fingerprints for recent duplicates; older prefixes are skipped only when catalog verification established them or the trusted application checkpoint covers them. Future noncontiguous or conflicting output fails. An empty recovery source cannot assert its starting sequence when history already exists. `requiresRefresh()` identifies a stopped or unqualified source; `refresh()` explicitly rebuilds the catalog after recording catches up or a generation changes. Idle polling never rescans or allocates a catalog. `LIVE` describes following an active recorded source after its startup prefix, and does not establish feed freshness or execution readiness.

All owners use one thread, fixed buffers, and preallocated maximum-message fragment assembly. Archive/Aeron passed to a consumer remain caller-owned. Delivery supports local IPC and configured UDP replay endpoints with protocol recording authority. The separate-driver loopback test explicitly binds UDP publication interfaces and covers remote control, fragmented catch-up and generation refresh; it does not qualify distinct-host networking, latency, power loss or multicast fan-out. Automatic requalification policy remains application-owned and cold.

Consumers using the optional `examples-binance` application decode `BookResult` at the canonical payload boundary to read BBO, native frontier, coverage, scales and
validity at that core cursor. Its `observation` field retains the full original inner SBE message, including tagged
SBE collector bytes. That module supplies the generated market codecs; see the [market-state contract](../docs/market-state-core.md).
