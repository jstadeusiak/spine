# Sample launchers and build support

Reviewed Aeron samples: `093fd4c49527feda9b99606fd165d59626fabfdc` (master, `1.54.0-SNAPSHOT`). The Java sample
implementations match the pinned 1.53.0 source jar; launchers still depend on their checkout/build layout.
Reviewed cookbook: `6fc95e9b07a9a25d9ed7cda10508d5ecde924fa0`.

## Launch and configuration patterns

The Bash/Windows pairs resolve their own script directory and call a shared Java launcher. `java-common` requires
`JAVA_HOME`, reads the checkout's `version.txt`, and supplies module opens plus experimental/diagnostic JVM flags and
ParallelGC. These flags describe the sample setup; choose GC/safepoint settings from measured deployment behavior.
`run-java` constructs a classpath to the built `aeron-all` jar, passes JVM options and executes the selected main.
The logging launcher itself contains no explicit `-javaagent`; property names alone do not document instrumentation
installation. Keep driver/client configuration and observability overhead visible in benchmark manifests.

The small publisher/subscriber/stat wrappers demonstrate process boundaries, not different protocol implementations.
Several omit forwarding their command-line arguments. Consult the individual wrapper before assuming a supplied
properties file reaches the application. Windows and Bash wrappers occasionally differ: Windows streaming-publisher
adds sample/bounds-check flags absent from its Bash counterpart. Quote channel URIs containing shell separators.

Throughput launchers set small 32-byte messages, large message counts, 8 KiB MTU/socket windows and often disable
bounds checks. IPC MTU affects fragmentation independently of network path MTU. These runs do not represent Spine's
fragmented 64 KiB observations, forced producer spool or crash/recovery envelope. Keep checks enabled in correctness
verification, declare transport/storage flags before traffic, and separately warm realistic message sizes/sessions.

The Archive profile files distinguish dedicated throughput, shared standard and shared/invoker lightweight modes.
All use file-sync level zero, which records via OS page cache; changing sync level changes the measured storage and
failure promise. High-throughput uses a 1 GiB segment, 1 MiB I/O batch, aggressive driver idling, 2 MiB sockets/window
and simulated spy connections. Lightweight requires its invoker to make progress. Their values are examples, not
Spine acceptance defaults. Archive README connects recording/replay startup, recorder counters, repeat/warm-up and
sync levels; its replay-merge example uses dynamic MDC, which is distinct from native multicast.

## Host operations and demonstrations

The C driver wrappers set `AERON_*` variables and run a checkout-built native driver. Dedicated spin/noop and shared
spin profiles trade CPU for polling delay. The thread-affinity helper reports CPU placement; it does not set affinity.
The Linux qdisc example changes loopback traffic-control state and adds 5% loss/10 ms delay on one UDP port.
The loss-rate C driver installs a loss interceptor with a 0.2 rate. These are useful fault-injection ideas; reproduce
them in an isolated harness with an explicit restoration/lifecycle policy rather than running them as setup.

Cluster launchers create three JVMs with member IDs and separate logs, or run inside Linux namespaces for distinct
network paths. Namespace setup creates two bridged subnets and `ns_node0..2`; the auction namespace launcher refers
to `ns_cluster0..2`, so these scripts are not a ready consistent deployment recipe. Namespace setup/removal and the
remote test launch server are operational tools with host effects. The namespace Cluster script also exposes an
unauthenticated JMX configuration: its sample convenience is not a production default.

The two raw `hack-*` wrappers name classes absent from this reviewed tree; current Java selector samples have
different names. Record such stale launchers in coverage rather than treating a wrapper's existence as proof it runs.

## Cookbook repository support

The root build uses Java 21/Zulu tooling, warnings-as-errors and common dependency repositories. Module builds route
SBE generation and executable/sample tasks; copying the root build is unnecessary for Spine. The version catalog
pins Aeron 1.52.1, Agrona 2.5.0 and SBE 1.39.0, while Spine uses 1.53.3/2.6.1/1.40.2. The current wrapper selects
Gradle 9.6.1 despite the README's older 8.5 requirement. README explicitly calls this demonstration code.

Checkstyle enforces formatting/naming and suppresses generated sources; that is code-quality support, not runtime
correctness. CI installs Java 21 and invokes the build; Dependabot checks Gradle dependencies. Git attributes control
line endings, and ignores exclude binaries/runtime data. The Gradle wrapper jar/scripts bootstrap Gradle and have
no Aeron runtime pattern; binary contents are inventoried, not decompiled. Apache license text is legal metadata.
