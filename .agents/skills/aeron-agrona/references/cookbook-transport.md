## Version boundary for Spine

The cookbook [version catalog](https://github.com/aeron-io/aeron-cookbook-code/blob/6fc95e9b07a9a25d9ed7cda10508d5ecde924fa0/gradle/libs.versions.toml) pins **Aeron 1.52.1, Agrona 2.5.0, SBE 1.39.0 and JUnit 6.1.1**. Spine currently pins **Aeron 1.53.3, Agrona 2.6.1, SBE 1.40.2 and JUnit 5.10.2**. Cookbook uses Java 21 and root toolchain vendor Azul; that vendor requirement is packaging, not an Aeron protocol property. Its Docker setup/agent scripts pin **Aeron 1.47.0** independently of the catalog. Do not combine those versions silently or upgrade Spine to make an example compile.

Historical source checks used Aeron 1.53.0 and Agrona 2.6.0 for the demonstrated `AeronArchive.replicate`, `tryClaim/commit/abort`, `CopyBroadcastReceiver`, clock and Snowflake APIs; verify the current pins before reuse. API presence is not behavioral or recovery acceptance. Regenerate any adopted SBE schema using Spine SBE 1.40.2, retain declared generation inputs/output ownership, and test exact layout/header/field-order behavior; generated cookbook source is not checked in. Keep Spine schema identities, payload limits and exact version validation. The cookbook async schema100 is unrelated to Spine schemas.

## Patterns to apply deliberately

- **Owned lifecycle and bounded progress:** construct resources under an owner, close runners before their clients/drivers, clean up partial startup, and close every owned publication/subscription/archive/AsyncConnect. Return meaningful `doWork` counts; many demos return0 after real work, forcing the idle strategy to sleep or spin incorrectly. Replace blocking callbacks/readiness loops and fixed three-attempt sends with explicit bounded state and retained pending bytes. Classify terminal offer statuses rather than retrying forever or silently advancing after failure.
- **Reuse without unsupported allocation claims:** reusable `UnsafeBuffer`, fixed buffers, SBE flyweights and ring-buffer claims reduce allocation/copies. Expandable buffers allocate when they grow; ASCII/UTF-8 String decoding, UUID correlation creation, timer/message/event records, logging and test HashSets still allocate. Direct-memory allocation also has cost and lifetime. A whole-sample zero-allocation claim requires measurements under its actual JVM/workload, with warmup and exceptions considered.
- **Complete frames and offsets:** callback offsets matter. Plain `FragmentHandler` is enough only for the tiny fixed-message assumption shown. For Spine 64KiB frames, assemble fragments before validating/applying, send exact encoded length, validate schema/template/version/block length/varData bounds, and do not retain a borrowed callback view beyond its lifetime.
- **Topology is a contract:** OneToOneRingBuffer is SPSC; ManyToOneRingBuffer is MPSC with one reader; broadcast supports multiple receivers but can lap slow ones and supplies no producer backpressure. Each successful ring claim must be committed or aborted. Neither ring nor broadcast substitutes for Archive durable history, logical cursor continuity or producer admission receipts.
- **Published versus recorded:** a positive offer/publication position is local transport progress. The local Archive example waits on a session/archive-pinned RecordingPos before proceeding; carry the complete-message fence and lifecycle validation into the real pipeline. Recording-event logs are observability. They are not replicated durability, power-loss proof or a consumer checkpoint.
- **Remote replay versus replica continuity:** resolve ephemeral UDP endpoints before requesting replay, pin replay identity and paginate descriptor searches. A physical Header.position can resume a byte-identical replicated recording; unrelated generations require Spine logical cursor/catalog mapping. Validate destination recorded extent and history before switching. The replication sample performs a planned switch, not automatic Cluster failover or lossless remote recovery.
- **Time and identity:** source capture timestamps, local monotonic timeout clocks, epoch timer deadlines, Snowflake IDs and Lamport clocks solve different problems. Preserve units, missing timestamps and uncertainty. None replaces the committed canonical log UUID/sequence or proves external-clock synchronization.

## Module guide

| Module | Pattern | Important limit |
|---|---|---|
| aeron-core | UDP request/reply handshake with reusable SBE codecs | Three-attempt loss, blocking callbacks, minimal reply validation |
| aeron-mdc | Dynamic MDC publisher and two remote subscribers | Ignored offers, no logical recovery; disposable Docker addressing |
| agrona | SPSC/MPSC claims, broadcast, atomics, clocks and ID tests | Known counter/sender2 defects; no whole-sample allocation proof |
| archive-core | Local recording acknowledgement and session-pinned replay | Deleted startup data, first100 lookup, unbounded waits |
| archive-multi-host | Remote Archive async connection and UDP replay | Remote replay alone does not establish replica continuity |
| archive-replication | Archive-owned copy plus physical-position planned switch | Extent/identity verification and durable restart absent |
| async | Correlated timer commands/events and cancel/fire race | Lost output after bounded offers; wall-clock/O(n) demo timer state |
| ipc-core | Embedded IPC ownership and success-preserving retry | Entire buffers sent and work counts suppressed |
| sbe-core | Header/layout/order/null/group codec tests | Tests intentionally allocate; checks do not validate arbitrary input |
| sbe-protocol | Schema/code generation with optional precedence checks | Different tool version, large schema bounds, shared generation output |
| theory | Lamport causality and deterministic local reducers | No consensus, persistence, real snapshot or allocation claim |

## Minimal followups for Spine

Use this reference to select a justified pattern, then inspect the exact pinned implementation before adding code. The closest already-used patterns are explicit resource ownership, session/archive-pinned recording counters, generated SBE header/body wrapping, borrowed-buffer callbacks and logical cursor continuity. Keep Spine contracts: exact proposal retries, application-owned capture before admission when process-loss recovery is required, one Cluster input commit with direct canonical output, complete recorded fences, verified generation continuity and explicit unavailable-history failure. Add no transport/timer/container wrapper solely because a demo contains one.

For allocation work, profile the current hot path first. Spine preallocates primitive Agrona maps, reusable flyweights, digest state and output buffers, with strict warmed allocation gates for its owned paths. Setup, restore and cold catalog qualification have separate budgets. The forced producer prepare/ACK cycle and its measured fsync cost belong to the historical implementation. These examples justify mechanisms, not a new throughput, allocation, power-loss or deployment claim.
