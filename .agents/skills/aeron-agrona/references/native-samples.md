## Transferable patterns and boundaries

- **Asynchronous control, explicit lifetime:** C registers publications/subscriptions asynchronously and polls registration results; C++ add/find follows the same control-vs-data separation. C image references need matching release; C++ shared_ptr/RAII/scope cleanup has a different ownership model. Add bounded deadlines and cleanup on every partial failure. Do not assume a registered publication is connected, committed or recorded.
- **Borrowed frames and assembly:** pointer/buffer+offset+length callbacks are borrowed. Assembling before a message counter/decoder distinguishes complete payloads from Aeron fragments. Basic subscribers, rate subscribers and ping echoes illustrate this. None validates Spine schema/log/cursor merely by assembling. Keep the production framing/continuity checks and explicit wire byte order; native host uint64/time_point writes are demo encoding, not portable SBE layouts.
- **Offer versus claim:** offer copies payload into a publication log and supports fragmentation within supported bounds. tryClaim provides an unfragmented region up to maxPayloadLength; write at the claim location and commit, or abort every successful claim on failure. An exclusive publication has one application writer, but an exclusive offer still copies. Spine 64KiB complete frames need the current fragmentation path unless a compatible transport configuration and acceptance test justify a different choice.
- **Truthful backpressure and progress:** temporary backpressure/admin action may be retried; closed/max-position/error conditions require explicit failure handling. Busy spin is a CPU policy, not a throughput guarantee. Several samples count attempted/requested messages after failed offers or interruption; use actual successful, recorded and applied counts and a finite final fence. A sample ratio that counts every negative result is not pure backpressure.
- **Measure the declared path:** RTT examples use one outstanding echo, sender-local monotonic timestamps, warmup then histogram reset. Their refreshed pre-offer timestamps exclude earlier retry/admission delay, so they are not equivalent to Spine prepare-to-durable-ack or schedule-to-application measurements. C++ time_point raw encoding is ABI-specific; no cross-host subtraction or one-way synchronization is established. Check HDR range/return values, completed sample counts, payload sizes, topology, pretouch policy, CPU/idle strategy and startup separation when interpreting timing.
- **Single-writer rate counters:** padding and acquire/release publication improve observation cost, but load-plus-store increments require one updater. Independently sampled byte/message counters are not an atomic application state or a recorded fence. Separate reporter threads/logging can affect the measured workload; preserve scope/join order before their referenced state is destroyed.
- **Diagnostics versus guarantees:** CnC counters, heartbeat, distinct-error and loss reports help isolate transport/driver faults. They do not prove canonical sequence continuity, checkpoint durability, Archive retention or exactly-once application effects. DriverTool termination is an authorized administrative action, not a passive diagnostic.

## Smallest useful applications to Spine

Keep the Java architecture and current durable contracts. The useful immediate review questions are whether the owner closes every transport handle after failure, counts complete assembled messages, distinguishes temporary offer failure from terminal status, respects claim size limits and measures an explicitly named start/end boundary. Performance work should reuse the existing synthetic gate/profile and add diagnostics only where they explain a measured bottleneck. Native stack storage, claims, pretouch or rate reporters do not remove producer fsync cost, establish power-loss safety, prove whole-path zero allocation or validate live-feed/HFT capacity.
